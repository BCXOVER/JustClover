# Skeet Motion + BT — CS:GO Legacy 8802, Windows x86

Сборка на основе предыдущей обычной версии с четырьмя патчами.
Готовая DLL: **`bin/skeet.dll`**. Используйте её вместо DLL предыдущего архива.
`bin/injector.exe` — тот же загрузчик из этой обвязки. Одновременно две версии
загружать не нужно. Lua для новых переключателей не требуется.

## Где находятся настройки

**Ragebot → Other**, в правом блоке, в начале списка.
Блок выбирается по расшифрованному родному имени `Other`, а не по индексу:
прежний индекс 1 попадал в `Aimbot` из-за отдельного блока `Weapon type`.
Используются штатные чекбоксы и ползунки меню.

| Настройка | Диапазон | По умолчанию |
|---|---|---|
| Patch: coherent interpolation | вкл/выкл | вкл |
| Interpolation gap (ticks) | 0–16 тиков | 8 |
| Patch: adaptive extrapolation | вкл/выкл | вкл |
| Extrapolation horizon (ticks) | 0–8 тиков | 2 |
| Patch: bounded backtrack | вкл/выкл | вкл |
| BT depth (ms) | 0–200 мс | 200 |

Три прежних переключателя `history guard`, `strict hit chance`,
`64-sample hit chance` и `consistent records` также находятся справа.
Все семь галок изначально включены; ранее сохранённые настройки могут изменить
состояние после загрузки. Оформление обычного меню сохранено.

## Что изменено в расчётах

**Интерполяция.** Раньше исходный выбор точки мог построить промежуточный
тик 98, а подготовка состояния скопировать запись тика 94.
Теперь родная процедура интерполяции ядра готовит полную запись, и её же
используют выбор точки, матрицы попадания и последующее применение.
Сохраняются родные преобразования углов и дополнительные варианты матриц,
когда они валидны у обеих исходных записей.

`Interpolation gap` задаёт максимальный разрыв между реальными записями,
который разрешено заполнять. При 0 промежуточные тики не добавляются.
Повышение до 16 допускает более редкие обновления, но не делает устаревшую
историю точнее. Начальное значение 8 выбрано умеренным.

**Экстраполяция.** Из двух или трёх реальных записей оценивается перемещение
за тик. При наличии трёх согласованных вертикальных образцов учитывается
вертикальное ускорение. Резкий разворот отклоняется; поворот или сильное
изменение скорости сокращают горизонт до одного тика.

Каждый шаг проверяется протяжкой player hull через `EngineTraceClient004`.
Кандидаты со столкновением или началом внутри препятствия отклоняются;
более короткий свободный прогноз остаётся доступен. Используется
консервативный стоячий hull, поэтому низкие проходы при приседании могут
отклоняться. Если интерфейс трассировки недоступен, будущие позы не создаются.

Ползунок — верхний предел, а не обязательное количество тиков.
Фактический горизонт также ограничивают интервал обновлений, текущее время,
родное допустимое временное окно, непрерывность истории, скорость и
максимальное перемещение 32 единицы. При 0 будущие тики не добавляются.
Пинг дополнительно к позиции не прибавляется.

В прогнозе смещаются положение и все валидные мировые матрицы попадания.
Будущие анимации, смена позы и действия противника не генерируются.
Неидентифицированные поля исходной записи сохраняются.

**BT.** `BT depth` ограничивает возраст кандидата относительно последней
реальной записи. Например, 50 мс при 64 tick оставляет не более трёх старых
тиков. Значение 0 оставляет последнюю запись и допустимые будущие прогнозы.
Патч сужает родной диапазон по возрасту; серверное окно назад не расширяется.
Глубина в миллисекундах округляется вниз до целого тика.

Проверяются конечность геометрии, готовность матриц, порядок и границы кольца,
скачки больше 64 единиц и родной стоп-маркер истории. Опции фиксируются на
одну проверку попадания; подготовленные позы повторно используются обоими
селекторами и применением. Устаревший кэш при обновлении истории отклоняется.

`consistent records` сохраняет прежний строгий отбор реальных записей,
когда новые интерполяция и экстраполяция выключены. При включённых новых
режимах согласованность подготовленной позы обязательна. Чтобы сравнить
полностью исходный путь выбора записей, выключите эти три галки и BT;
прежние патчи порога попадания и 32/64 образцов переключаются отдельно.

## Проверки и ограничения

DLL/EXE пересобраны как Windows PE32. В закрытых x86 fixtures выполнены
исходный селектор, родная интерполяция и подготовка применения вместе
со скомпилированными новыми обработчиками. Проверены промежутки 1–16 тиков,
четыре набора по 19 матриц, повороты через ±180°, кольцо до 32 записей,
все значения горизонта 0–8, BT при 64/128 tick, ограничения времени,
смена галок, столкновения и инвалидирование кэша.

Отдельно выполнены настоящий конструктор ползунка и декодер имён ядра.
Проверки трёх прежних патчей, загрузчика, ресурсов и упаковки прошли.
Точные результаты и границы каждой проверки — в `reports/`.

В эмуляции функции TLS, копирования памяти, скалярной тригонометрии и
ответы движка заменены контролируемыми заглушками. Сам игровой клиент,
защищённый запуск ядра и сервер не запускались. Работа меню в игре,
FPS и реальное улучшение попаданий при пинге 100+ пока не измерены.
Установка всех ползунков на максимум не гарантирует лучшую стрельбу.

## Исходники и сборка

В архиве находятся полная обвязка, открытый C++ код новых патчей, проверки,
дифф относительно предыдущей версии и SHA-256 каждого файла.
Бинарный ресурс исходного ядра сохранён побайтно; патчи устанавливаются
в память перед вычислением его штатной контрольной суммы. Высокоуровневый
полный исходник защищённого ядра не восстановлен.

Основа: предыдущая DLL SHA-256
`baf7139e22d99a5cc27696113a4681b1a261a90f739cd0518ddcd54d5d4b6580`.

```sh
python -m pip install -r requirements-build.txt
python build_windows.py
python tools/audit_blend.py
python tests/validate_motion.py
python tests/validate_rage_controls.py
python tests/validate_native_menu.py
python tests/validate_scan_patch.py
python tests/validate_precision.py
python tests/validate_release.py
python tests/validate_resolver.py
```

Для генераторов тестовых переходников также нужен `g++`.
`validate_records.py` проверяет отдельно сохранённую предыдущую реализацию
строгого отбора; в новой DLL её установку заменяет `motion_patch`.
