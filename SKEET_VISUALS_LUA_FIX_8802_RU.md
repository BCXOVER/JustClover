# Skeet — новые иконки Visuals и исправление перезагрузки Lua

CS:GO Legacy 1.38.8.1, build 8802, Windows x86.
Готовая DLL: **`bin/skeet.dll`**. Используйте её вместо предыдущей версии.

## Что сделано

Вкладка **Visuals** сохраняет полосу `Category` из предыдущей сборки.
Иконки категорий перерисованы на единой сетке: плавный силуэт, круг запрета,
плюс, глобус с контурами материков, миндалевидный глаз и знак Danger Zone.
Края сглажены 16 подвыборками на пиксель; маски пересчитываются только при
смене DPI. Активная иконка светлая, наведение подсвечивает остальные.
Расположение групп основано на четырёх кадрах пользователя:

- Enemy: `Enemy ESP` слева, `Enemy models` справа.
- Team: параметры командного ESP и `Team models`.
- World: `Other ESP` слева, `Colored models` и `Effects` справа.
- View: `View` слева и `HUD` справа.
- Danger Zone: сохранены имеющиеся в CS:GO параметры этого режима;
  пятая иконка показана при наличии соответствующих элементов ядра.

Категории переключаются родными кнопками. Чекбоксы, ползунки, цветовые
пикеры, выпадающие списки, кнопки и горячие клавиши созданы штатными конструкторами ядра.
Они связаны с исходными значениями и обработчиками; исходные объекты,
их родители и индексы сохранены для конфигов и ссылок на настройки.
Динамическая видимость и отображаемые значения обновляются после изменения
параметров. Родная прокрутка длинных групп остаётся доступной.

Названия и порядок доступных элементов приближены к кадрам. Состав настроек
соответствует возможностям исходного ядра CS:GO: отсутствующие функции CS2
не добавлены в виде неработающих галок. Например, вместо придуманного
`Avatar` остаются настоящие настройки ESP этой DLL.

В исходном CS:GO ядре многие параметры Player ESP общие для врагов и команды.
Поэтому группа `Team ESP (shared)` использует те же значения, а отдельные
настройки моделей команды используют собственные исходные привязки.
Переключение категории само по себе не меняет игровые значения.

На первой открытой отрисовке выполняется привязка интерфейса.
Исправлена причина возврата старого Visuals при загрузке/выгрузке Lua:
изменение списка элементов больше не выключает новый слой навсегда.
При изменении состава Visuals/Misc привязки пересоздаются в тех же группах.
Выбранная категория и общие значения исходных настроек сохраняются.
Кнопки категорий остаются на месте вместе с обработчиками.
Поддерживаются также добавленные Lua чекбоксы, кнопки, ползунки, combobox,
multiselect, color picker, hotkey и статические подписи в исходных группах.
Кнопки вызывают обработчик исходного объекта.

Отложенный обработчик проверяет живой состав меню до обращения к исходному
Lua-объекту. После удаления объекта закрываются старые popup/захваты ввода,
а удаление наших представлений откладывается до следующего кадра, за пределы
текущего вызова обработчика. Исходные объекты и их значения не уничтожаются
и не переносятся. В кадрах без изменения состава меню новые объекты не создаются.

При неподдерживаемом типе элемента внутри Visuals (например, textbox/listbox)
штатный интерфейс остаётся безопасным резервным вариантом. После выгрузки
такого Lua категории автоматически возвращаются; повторного запуска DLL
не требуется. Это не полная реализация всех типов пользовательских Lua-виджетов.
Если удалены сами наши группы, восстанавливается штатный Visuals.

## Инвентарь и видимость скинов

В этой версии скинченджер и сетевое поведение не изменены.
Локальное добавление выбранных скинов в игровой инвентарь потребовало бы
отдельной реализации inventory changer. Это не создаёт предметы в Steam
и не даёт права владения/обмена ими.
Чтобы выбранные локальные скины видели другие владельцы нашей сборки,
потребовалась бы отдельная синхронизация и их отображение на каждом клиенте.
Одного наличия Skeet у обоих игроков недостаточно. Такой обмен в эту DLL
не добавлен; серверные данные о предметах остались прежними.

## Что ещё не сделано

**Это переработка Visuals, а не полная копия всех вкладок Gamesense CS2.**
На всех четырёх присланных кадрах открыта вкладка Visuals.
Отдельного кадра Skinchanger не было, поэтому её штатное оформление
сохранено. Остальные вкладки также оставлены родными.

Указанное видео: https://www.youtube.com/watch?v=GR6BduR0QBM.
YouTube возвращал 403 в этой среде, включая повторный запрос с расширенным
сетевым доступом. Видео не просматривалось; использованы присланные кадры.
Для точного оформления Skinchanger нужен её отдельный кадр или доступный файл.

`Visuals_layout_preview.png` и `Visuals_icons_preview.png` — схемы производственной геометрии и иконок
с условно показанными родными контролами. Это **не скриншот игры** и не
подтверждение точного совпадения интерфейса в клиенте.

## Патчи

Основа — предыдущая сборка AlwaysOn. Наш BT-патч отсутствует.
Хитскан и предикт постоянно включены; дополнительных галок и ползунков
для них в меню нет. Предикт ограничен 2 тиками, промежуток интерполяции — 8.
Штатная историческая обработка исходного ядра сохранена.

## Проверки

- 42 проверки скомпилированного Windows x86 кода создания привязанных контролов.
- 6 проверок настоящего C++ переходника изменения значений и видимости.
- Раздельное владение строками combobox, исполнение родного обновления его
  выбранного пункта и сохранение inline-буфера multiselect.
- 20 сценариев переключения категорий при четырёх масштабах; проверена
  горизонтальная полоса без лишней прокрутки.
- 48 сравнений исходной x86 отрисовки меню с настоящим скомпилированным
  переходником: аргументы, порядок вызовов, стек и сохраняемые регистры.
- 53 проверки жизненного цикла: 12 повторных циклов загрузки/выгрузки,
  удаление страниц исходного Lua-объекта и модели до вызова отложенного
  обработчика, добавление/удаление целой группы, замена указателя значения,
  восстановление после неподдерживаемого типа и удаление нашей группы.
- 180 проверок геометрии/иконок, проверки маршрутизации и прежних патчей,
  ресурсов DLL/EXE и контрольных сумм архива.

В fixtures функции выделения памяти, обработчики UI и ответы отрисовщика
заменены контролируемыми заглушками. Защищённый запуск ядра, полный процесс
игры и ввод мышью в реальном клиенте не выполнялись. Реальный внешний вид,
загрузка конфигов в игре, FPS и стабильность в CS:GO ещё требуют проверки.
Отчёты находятся в `reports/`.

## Исходники

В архиве — обвязка, открытый C++ код новых компонентов, тесты, дифф
`Visuals_Lua_Fix.diff` и `SHA256SUMS.txt`. Бинарный ресурс исходного защищённого
ядра сохранён побайтно; его полный высокоуровневый исходник не восстановлен.

```sh
python -m pip install -r requirements-build.txt
python build_windows.py
python tests/validate_visuals.py
python tests/validate_motion.py
python tests/validate_scan_patch.py
python tests/validate_precision.py
python tests/validate_release.py
python tests/validate_resolver.py
```

Для генераторов тестовых переходников нужен `g++`.
Для необязательной схемы установите Pillow и выполните
`python tests/render_visuals_preview.py` после проверки Visuals.
