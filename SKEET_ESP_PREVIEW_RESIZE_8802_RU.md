# Skeet — ESP preview, цветовые пресеты и исправление масштабирования

CS:GO Legacy 1.38.8.1, build 8802, Windows x86.
Готовая DLL в архиве: **`bin/skeet.dll`**.

## Панель ESP / Appearance preview

В Visuals добавлена кнопка **Preview** в верхней строке категорий.
Она показывает/скрывает отдельную панель. Панель размещается справа или слева
от меню; если по краям нет места, остаётся в пределах экрана поверх меню.
Крестиком в заголовке панели её можно закрыть, чтобы открыть закрытые ею
настройки. Кнопка Preview возвращает панель.

**Шестерёнка снизу справа** открывает настройки панели:

- Enemy / Team / Local player / Viewmodel — объект предпросмотра.
- Bounding box, Health bar, Name, Skeleton, Weapon icon/text, Ammo, Flags —
  переключатели настоящих доступных настроек ESP противника/союзника.
- Glacier, Amethyst, Crimson, Champagne — новые цветовые пресеты для родных
  настроек моделей противника, local player и weapon viewmodel.

Пресет включает соответствующую родную настройку и меняет её цвет. Для
материала выбирается подходящий реальный вариант по имени, а не по номеру
строки. Если Metallic отсутствует, используется Solid, если он есть.
Если обоих нет, текущий материал сохраняется и применяется только цвет.
Недоступные настройки показываются неактивными. Переключатель Flags
восстанавливает предыдущую выбранную маску, при первом включении выбирает
доступные флаги; родное ограничение непустого выбора сохраняется.

**Предпросмотр схематичный:** процедурный манекен/условная винтовка, не
настоящая игровая CT/T-модель из видео. Он показывает расположение ESP и
выбранные цвета; не воспроизводит точный игровой шейдер, агент или скин.
Новые игровые шейдеры/модели не добавлены. Rotate поворачивает этот манекен.
Пример здоровья/оружия/флагов в панели не является информацией о живом враге.

Изменения цветов и ESP проходят через родные значения и обработчики:
сохраняются обычным конфигом Skeet. Вид панели, её открытая шестерёнка и
поворот сохраняются в текущем сеансе при изменении размера и Lua-перестройке.
Это не отдельная постоянная запись UI-настроек между запусками игры.

Клики панели проходят через оконный маршрутизатор: исходная оконная
процедура вызывается для остальных событий. При пересечении с меню
панель забирает собственные клики. Смена игровых значений выполняется
в кадре отрисовки, не из оконной процедуры. Открытые родные popup-окна
получают приоритет; панель временно скрывается. При потере фокуса, смене
геометрии или уничтожении окна отложенный клик отменяется.

## Исправление цикла «меньше → больше → обратно»

Штатный HandleDPI умножает базовые размеры на DPI. Раньше новые панели
записывали туда уже масштабированные пиксели, а изменение геометрии не
всегда пересчитывало ширину дочерних элементов. Теперь пиксельные и базовые
размеры разделены для панелей, кнопок и списка скинов. При изменении
размера/DPI вызываются родные обработчики и затем пересчитывается раскладка.
Временные состояния мыши/открытых списков сбрасываются без сброса значений.
Перемещение и независимое растягивание новых подпанелей отключены:
их расположением управляет общая раскладка.

Исправлено соглашение вызова IRenderer::GetZBuff в SDK: родная функция
возвращает float в XMM0, а не в x87. Проверены чтение и восстановление
глубины через настоящие функции рендера на пяти значениях.

Сохранены все 13 виртуальных методов Child. Методы 9/10 теперь проходят
через переходники, вызывающие исходные обработчики resize/DPI; остальные
служебные методы сохранены. Проверены 144 сценария, включая повторное
использование одного объекта после смены DPI и возврата размеров, а также
настоящий обработчик DPI Listbox на четырёх масштабах.

## Skinchanger

Три панели по присланному кадру:

- `Model customization` — слева сверху, настройки моделей.
- `Settings` — слева снизу, исходный `Filter by weapon`.
- `Weapon skin` — справа на всю высоту: исходные переключатели, качество,
  seed, список скинов с поиском и поле имени, если эти элементы есть в ядре.

Используются настоящие исходные значения и обработчики. Исходные объекты,
их родители и индексы остаются на месте; новые представления создаются
штатными конструкторами UI. Выбор модели, скина, StatTrak, качества и прочих
параметров передаётся исходному ядру. Неработающие настройки не добавляются.

Данные списков и их строки копируются отдельно. Поиск/прокрутка принадлежат
новому списку, выбранное значение связано с исходной настройкой. При смене
оружия обновляются указатели значений, наборы моделей, скинов и индексы
фильтрации. Текстовое поле пересылает исходному обработчику свой буфер.

У выбора моделей могут быть специальные родные классы с приватными данными
схемы/коллекций. Их отрисовщик строк вызывается на настоящем исходном объекте;
приватная память этих классов не копируется в обычный combobox. У обычных
combobox с известными моделями The Professionals предусмотрено двухстрочное
представление. В списке скинов маркеры теперь показывают редкость из данных CS:GO Legacy:
обычный/промышленный, армейский, запрещённый, засекреченный, тайный и
контрабандный классы получают свои цвета. Выделенная строка сохраняет
цвет редкости маркера; родная подсветка выбранного названия остаётся.

Каталог содержит 1147 раскрасок и 1713 совместимых комбинаций предмет/раскраска.
Он получен из схемы Valve и английской/русской локализаций, опубликованных
SteamDatabase в GameTracking-CS2, commit
`e63fc7fdb8dfb4f1873f0db214c0cc16613d5beb` (историческое дерево CS:GO).
Происхождение, SHA256 схемы и исходные факты: `data/skin_rarity_catalog.json`.
Генератор: `tools/build_skin_rarity.py`.

Итоговая редкость вычисляется с учётом базового предмета, а не только
внутреннего ранга paint kit. Если отображаемые раскраски однозначно задают
один предмет, используется этот контекст. При недостатке контекста либо
неизвестном/неоднозначном названии маркер серый. 37 раскрасок требуют контекста
либо не имеют однозначных данных комбинации; цвет им не назначается наугад.
Случайное совпадение порядкового номера строки с ID раскраски не считается
совпадением: проверяется также локализованное название.

Защита от удалённых Lua-элементов и перепривязки моделей проверяет живое
владение перед вызовом исходного обработчика. Удаление наших представлений
выполняется между кадрами. При несовместимом составе исходного интерфейса
остаётся штатная вкладка; после изменения состава привязка может восстановиться.

## Установленные игровые патчи

Новые изменения включены постоянно, без дополнительных галок. Установка идёт
в памяти до запуска ядра и расчёта его контрольной суммы; исходный ресурс
защищённого ядра на диске сохранён. Каждая точка сверяется с ожидаемыми байтами.
При несовпадении загрузка прекращается с сообщением об ошибке совместимости.

- Предикт требует минимум три пригодные записи. Горизонт — максимум 2 тика,
  не больше наблюдаемого разрыва записей и родного временного окна. Полный ping
  повторно не добавляется. Резкий поворот, изменение скорости, остановка,
  разрыв истории или столкновение отклоняют прогноз, включая прогноз на один тик.
- Каждый шаг проверяется трассировкой объёма игрока. Исходные записи не меняются.
  Для выбора точки и последующей проверки используется одна подготовленная поза;
  перенос согласован для всех четырёх доступных наборов матриц.
- Между близкими реальными записями доступна родная интерполяция до 8 тиков разрыва.
- Проверка хитшанса использует 128 разных seed вместо исходных 32. Увеличены
  стековый кадр и буфер направлений, перенесён объект применения записи.
  Порог округляется вверх; неудачное применение истории не допускается к проверке.

**128 — количество образцов рассеивания, а не точек multipoint на хитбоксе.**
Плотность пространственного хитскана не увеличивалась: отдельная безопасная
точка изменения multipoint в этом защищённом ядре пока не подтверждена.
Дополнительные трассировки увеличивают нагрузку этой проверки относительно
32 образцов. Улучшение FPS, процента попаданий или результата матча не измерено.
Собственное расширение/ограничение BT не добавлено; родная нижняя граница истории сохранена.

## Desync 60° и переданные игровые DLL

В `client.dll` 2023 года обнаружена инициализация границ yaw анимационного
состояния значениями −58°/+58° (RVA 0x43e928/0x43e932). Изменение клиентских
чисел не доказывает серверную разницу углов 60°. Патч «настоящие 60°»
в эту сборку **не добавлен**, число в меню не подменяется.

`client_panorama.dll` из архива собран в 2020 году; это старый клиентский
модуль, а не современный `panoramauiclient.dll`. Смешивать его привязки с
`client.dll` 2023 года нельзя. Отчёт: `reports/client_module_audit.json`.
Игровые DLL в релиз не включены и на хосте не запускались.

## Локальный инвентарь и главное меню

Не реализованы в этом релизе. Полученные DLL позволили подтвердить создание
предметов и часть API кэша. Однако штатный метод обновления экипировки отправляет
GC-сообщение; для полностью локального показа необходимы отдельная фильтрация
этой отправки, восстановление экипировки и проверенная привязка всех профилей
скинченджера. Подробности разбора: `Inventory_Integration_Status_RU.md`.
Общий обмен скинами между игроками по-прежнему отсутствует.

Варианты следующего оформления меню: `MENU_PROPOSAL_RU.md`.
Описание поведения предикта: `PREDICTION_IDEAS_RU.md`.

## Проверки и ограничения

- 144 проверки родного resize/DPI; проверка полной таблицы из 13 методов Child с пересылкой resize/DPI.
- Проверка каталога редкостей, контрольные примеры настоящих предметов,
  русские/английские имена, контекст и совпадения порядковых номеров.
- Проверки пресетов на трёх профилях, отсутствующем профиле и резервном материале;
  переключатели ESP, сохранение остальных значений и отказ после удаления источника.
- Проверки оконного ввода, цепочки оконных процедур и ABI отрисовки шестерёнки/настроек.
- 75 раскладок панели и 12 ограниченных поворотов процедурной геометрии.
- 42 проверки Windows x86 фабрики базовых контролов; 6 проверок привязок.
- Проверки Skinchanger: отдельное владение строками/listbox, настоящий
  native OnConfigLoad для списков/combobox, исходные callbacks, текстовое
  поле, фильтрация, смена моделей и удаление Lua-объектов. Деструкторы
  представлений исполняются из исходного x86 ядра с заменённым освобождением памяти.
- 54 проверки геометрии трёх панелей на шести масштабах DPI.
- 53 проверки жизненного цикла Visuals, включая повторные загрузки/выгрузки Lua.
- 48 проверок переходника исходной отрисовки меню, прежние проверки категорий,
  34 проверки резолвера, PE32 DLL/EXE и ресурсов.
- 98 172 проверки порога для 32/128 образцов; родные генератор, полный цикл трассировок
  и завершение перенесённого объекта.
- Совместная установка трёх патчей на трёх адресах выделения: 81 принадлежащий
  патчам байт инструкций, остальные байты образа сохранены.

**В игре эта сборка не проверялась.** Fixtures используют контролируемые
замены выделения памяти, обработчиков и отрисовщика. Защищённый запуск,
полный игровой процесс, реальное управление мышью и точное совпадение
со скриншотом не проверены. `Skinchanger_layout_preview.png` — схема
производственной геометрии с иллюстративными контролами, не кадр из игры.

## Сборка

```sh
python -m pip install -r requirements-build.txt
python build_windows.py
python tests/validate_visuals.py
python tests/validate_scan_patch.py
python tests/validate_precision.py
python tests/validate_motion.py
python tests/validate_release.py
python tests/validate_rarity.py
python tests/validate_resolver.py
python tests/render_skin_preview.py
python package_release.py
```

Для портативных генераторов проверок нужен `g++`; для схемы — Pillow.
В архиве также находятся исходники обвязки, тесты, отчёты и SHA256SUMS.txt.
Защищённый бинарный ресурс ядра и VM bytecode сохранены побайтно;
полный высокоуровневый исходник исходного ядра не восстановлен.
