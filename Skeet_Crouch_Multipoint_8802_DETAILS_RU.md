# Multipoint для присевших целей — Skeet Legacy 8802

Готовая DLL: `bin/skeet.dll`. Новая настройка **Ragebot → Other → Crouch multipoint**,
включена по умолчанию. Extropolate остаётся отдельным независимым переключателем.
Чтобы применить сборку, полностью перезапустите игру и замените файлы bin вместе.

Поправка действует на боковые точки головы, груди и живота. При duck amount
до 0.55 координаты остаются штатными. Между 0.55 и 0.90 применяется плавный
переход; при полном приседании расстояние боковой точки до центральной
умножается на 0.88 для головы и 0.82 для груди/живота. Центральные точки,
руки, ноги и шея сохраняются. Количество точек не увеличивается.

Степень приседа берётся из выбранной исторической записи противника, а не
из его текущего состояния на экране. Не требуется отдельный ползунок.
В выключенном состоянии и для стоящей цели обходятся helper и FXSAVE.
Изменение геометрии само по себе не доказывает рост процента попаданий:
проверки с реальными противниками/пингом здесь не выполнялись.

## Реальная интеграция

У Skeet предварительная точка имеет размер 0x18 (XYZ, native scale, hitgroup,
flags); оценённая точка позднего scan pool — 0x38. Модуль Neverlose из архива
пользователя использовал другой формат 0x50, поэтому его адреса/перехваты
не копировались. Заимствованы коэффициенты и линейная математика поправки.

Перехвачены только два вызова добавления боковых точек в 0x4332325f:
0x4335e8f2 и 0x4335eebb. Центральные вызовы 0x4335e8ca / 0x4335ee93 не меняются.
Исторический duck amount — raw record +0x3c (job+0x12c), захват которого
проверен по нативным инструкциям 0x433fd7f9..0x433fd80e. Центр для каждого
из двух путей берётся из его собственного локального объекта рабочего кадра.

Математика выполняется до оценки урона, трассировки и вероятности попадания.
В отдельной 24-байтовой копии на стеке меняется только XYZ. Все 12 байтов
метаданных остаются штатными. Исходный вектор генератора, центр, история и
копия lag record не переписываются. Нативный append получает копию и сам
добавляет её в прежнюю очередь; дальнейшая оценка использует новые координаты.

Перед изменением проверяются исходные CALL, реализация append, захват duck
и четыре контекста вызовов с расположением центров/аргументов. Сохраняются
flags, GP-регистры, x87/SSE и исходное поведение очистки стека. Буферы TLS
и выделение heap на точку не используются. Установка происходит до entry
защищённого ядра и его вычисления контрольной суммы.

## Проверки

- 899 случаев настоящего pre-scan append с production callback: оба пути,
  три расположения trampoline, частичный/полный присед, головы/корпус/конечности,
  OFF, неверные значения и нативный захват исторического значения.
- 504 из них подтверждают обход helper для OFF/стоящих целей.
- Исполнены два нативных фрагмента подготовки направления трассировки:
  они получают изменённые координаты из очереди.
- Проверены независимость чекбоксов, сохранение модели при перестройке UI,
  отсутствие дублей, прежние resize/DPI и Lua lifecycle.
- Совместная установка: шесть выделений исполняемого кода, 108 принадлежащих
  игровым патчам байтов инструкций. Этот модуль добавляет 10 байтов CALL.

Проверки выполнялись в закрытых x86 fixtures с подменой внешних API.
Игра и защищённый старт здесь не запускались. Старые отчёты модулей сохранены
только после побайтного сравнения их исходников; provenance включён в reports.
Сохранены прежние Extropolate, Skinchanger и исправление поиска агентов.
Полная логика resolver Neverlose не добавлялась; удалённые DT-модули и
собственный backtrack не восстанавливались.
