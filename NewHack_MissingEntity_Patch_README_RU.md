# Патч NEW HACK — CL_CallPostDataUpdates: missing ent 3

Изменения сделаны для проекта из приложенного `NEW HACK - Copy.7z`.

## Готовые файлы

В `ready/` лежат **injector.exe** и **missing_entity_fix.dll** (Windows x86).

1. Полностью закрой CS:GO после прежней загрузки чита.
2. Скопируй оба готовых файла в папку со своей рабочей `neverlose.dll` и сервером
   этой сборки. Сохрани прежний инжектор отдельно.
3. Запусти свой сервер, затем CS:GO Legacy и новый инжектор из этой папки.
4. В консоли появится `Missing-entity guard installed (or already present)`.
   Затем загрузится обычная `neverlose.dll`.

Новый инжектор сначала загружает маленькую DLL-патч, проверяет её успешную
инициализацию и только затем продолжает прежний путь загрузки Neverlose.
Если версия движка не совпала с проверяемой структурой, загрузка чита
останавливается с ошибкой вместо записи по предположительному адресу.
Инжектор и DLL-патч должны оставаться рядом. Обновление начинает действовать
после перезапуска игры; уже запущенный чит не выгружается автоматически.

**Основная neverlose.dll здесь не пересобиралась.** Используется твоя рабочая
DLL: готовый патч работает отдельно и не зависит от STL защищённого ядра.
Исходники проекта также исправлены: при полной сборке MSVC тот же обработчик
устанавливается из `neverlose::setup_hooks()` до запуска ядра. В решение
добавлен проект `missing_entity_fix`, выдающий DLL в общий каталог Release.

## Что исправлено

В предоставленном ранее engine.dll найдена точная ветка сообщения
`CL_CallPostDataUpdates: missing ent %d`. Движок берёт индекс из очереди,
ищет сущность, вызывает фатальную ошибку при nullptr, а после ветки ошибки
расположен вызов PostDataUpdate через её указатель.

Патч заменяет **двухбайтовую инструкцию** `FF 37` на `EB 18` только в этой
ветке отсутствующей сущности: она переходит к штатному продвижению очереди.
Живые сущности по прежней ветке получают PostDataUpdate с прежним аргументом.
Сохраняются цикл, счётчики, Begin/End и завершающее профилирование функции.
Не выполняются вызов Error и разыменование nullptr.

Адрес не зашит как постоянный: поиск ограничен исполняемыми секциями
engine.dll, проверяется 47-байтовый контекст, точная строка ошибки и единственность
совпадения. Учитываются ASLR и границы образа. В проверенной DLL RVA — `0xD7092`.
Замена выровненного слова выполняется атомарным CompareExchange16, затем
сбрасывается кеш инструкций и возвращаются исходные права страницы.
Повторная установка распознаётся и ничего не переписывает.
Патч действует только в памяти текущего процесса, engine.dll на диске сохраняется.

Это восстановление обработки исчезнувшей записи, а не создание поддельной
сущности №3. Какая именно операция скинченджера удалила её до обработки
пакета, по одному тексту Engine error не установлено. Другие причины
повреждения состояния игры этот патч не проверяет.

## Проверки и сборка

- На настоящих инструкциях исходного engine.dll воспроизведён missing ent 3.
- 128 случаев очереди: отсутствующие записи, все живые/все отсутствующие,
  исчезновение сущности во время предыдущего PostDataUpdate, последующие
  обновления, сохранение регистров/стека и завершающих обработчиков.
- 24 случая production runtime: ASLR, повторная установка, неизвестная версия,
  неоднозначная сигнатура, недоступная память, ошибки записи/защиты/flush.
- 46 проверок контекста и отказов, 9 случаев жизненного цикла загрузчика,
  PE32/ASLR/NX/импорты двух собранных файлов.

Тесты выполнялись в ограниченном x86-эмуляторе с подменёнными WinAPI/игровыми
интерфейсами. Игра, Steam и защищённый старт Neverlose здесь не запускались.

Готовые файлы собраны из изменённых исходников инжектора и patch_loader
компилятором Zig 0.13.0. Для повторения: `python build_missing_entity.py`
после установки `requirements-patch.txt`. Полная neverlose.dll требует
MSVC и исходного окружения из README.md (Release | x86); GNU STL для неё
не подставлялась. Сервер и бинарный модуль nl.bin сохранены побайтно.
Для тестов нужен исходный engine.dll: переменная `CSGO_ENGINE_DLL`.
Отчёты и суммы готовых файлов включены в архив.
