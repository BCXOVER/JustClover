# Патч проверки исторической записи и порога попаданий

Собранная Windows x86 DLL для предоставленной обвязки CS:GO Legacy.
Целевая ветка пользователя: 1.38.8.1, build 8802, csgo_legacy.
Это первый ограниченный патч сканирования. Новый алгоритм прогнозирования
движения, выбора точек или резольвера сюда не добавлен.

## Изменения поведения

1. В одном пути расчёта попаданий оригинальная функция пыталась применить
   историческую запись, но её результат не проверялся. Теперь при отказе
   сканирование прекращается через существующий путь очистки снимка.
   Например, это происходит при пустой истории или скачке позиции больше
   64 единиц. Успешное применение записи сохраняет прежний путь выполнения.
   Ветка, в которой запись изначально не выбрана, также сохранена.

2. В существующей проверке из 32 образцов требуемое число успешных
   проверок округляется вверх. При пороге 80% прежде принимались 25/32
   (78,125%), теперь требуется 26/32 (81,25%). Минимум остаётся равен 1.
   Это делает критерий строже; число выстрелов может уменьшиться.
   Количество образцов, генератор разброса и данные оружия сохранены.

Повышение фактического процента попаданий пока не измерено.
Собственный урон оружия патч не меняет.

## Установка и откат

В `bin/` находятся `skeet.dll` и соответствующий `injector.exe`.
Сохраните старые файлы отдельно и замените оба файла новой парой.
Используется прежний способ загрузки предоставленного проекта.
После ошибки инициализации или для отката перезапустите игру;
для отката верните исходную пару файлов.

Сначала проверяйте на локальном сервере. Реальный запуск этой DLL в
Windows и игре здесь не выполнялся. Полная совместимость оставшихся
фиксированных адресов исходной обвязки со сборкой 8802 не подтверждена:
конкретные `client.dll`, `engine.dll` и `gameoverlayrenderer.dll` пользователя
не предоставлены. CS2 не поддерживается.

## Что изменено в коде

- `source/skeet/scan_patch.h`: проверка точной версии исходного ядра,
  генерация двух x86-переходников, проверка ожидаемых инструкций,
  установка до запуска потока ядра, откат записей при ошибке сброса кеша.
- `source/skeet/skeet.cpp`: подключение патча. Установка выполняется перед
  исходным расчётом контрольной суммы в `recompile()`.
- `source/skeet/dllmain.cpp`: сообщение о применении патчей.

Адреса внутри оригинального ядра, база `0x43310000`:

| Место | Изменение |
| --- | --- |
| `0x4332FFB1` | Вызов применения записи через проверяющий переходник. |
| `0x43330178` | Округление требуемого количества успешных образцов вверх. |
| `0x433300C8` | Существующая ветка отказа с очисткой снимка. |

Исходный `skeet_cv.bin` встроен без изменения байтов. Изменения вносятся
в отображённый образ при запуске DLL. Для другой версии ядра загрузка
останавливается; произвольные похожие DLL не поддерживаются.

Полный исходник защищённого ядра не восстановлен. В `source/` остаются
оригинальные бинарные ресурсы и обвязка из предоставленного архива.

## Проверки

- DLL и EXE пересобраны в PE32 для Windows x86.
- 19 998 проверок исходных и изменённых инструкций порога: все проценты
  от 0 до 100, все количества успехов от 0 до 32, три адреса размещения кода.
- 72 сценария перехода после применения записи: успешный/неуспешный
  результат, отсутствие выбранной записи, оригинальные ветки пустой
  истории и скачка позиции. Проверены аргументы, стек, сохранённые
  регистры, возврат и однократная очистка на отказе.
- Проверка соответствия оригинальному ядру и отклонения изменённых
  участков. Проверка формата DLL/EXE и точного содержимого ресурсов.

Эти проверки выполнялись в эмуляторе x86 с заглушками интерфейсов
движка и очистки снимка. Они не заменяют проверку в игре.
Отчёты и контрольные суммы находятся в `reports/` и `SHA256SUMS.txt`.

Пересборка: установите зависимости из `requirements-build.txt`, затем
выполните `python build_windows.py`. Проверка машинного кода на Linux
требует также `g++`: `python tests/validate_scan_patch.py`.
